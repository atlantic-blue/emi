# `@emi/tokens`

The exported surface of `packages/tokens`, generated by `npm run generate:reference`.
Nobody writes this page by hand. The prose under each symbol is the documentation comment that
sits on it in the source, so this page cannot say one thing while the code says another.

65 exported symbols, across 7 files.

```

```

The application imports this to prove the workspace resolves at run time. A type import cannot
do it, because the types come off before the bundle runs.

### `ColourRole`

```
type ColourRole = 'ground' | 'text' | 'fill' | 'line';
```

What a colour is allowed to do. A fill and a text colour are separate roles because three of the
four phase fills fail the contrast floor as text.

### `ColourToken`

```
interface ColourToken {
  readonly value: string;
  readonly roles: readonly ColourRole[];
  /** The grounds this colour is measured against and approved to carry text on. */
  readonly textOn: readonly ColourName[];
}
```

A value and the rules that travel with it. A value on its own would let a screen put any colour
on any ground, which is the drift the contrast test exists to catch.

### `colours`

```

```

The palette. Every value here is the one the design publishes, and the token test holds that
published list, so a colour changed here fails the run until the design changes too.

### `colourNames`

The palette as data, in the order the brand document prints. A type cannot be read at run time.

### `colour`

### `hasRole`

### `relativeLuminance`

```

```

Refuses anything but a six digit hex, because a colour carrying transparency has no
contrast ratio of its own: what it sits on decides the answer.

### `contrastRatio`

```

```

The ratio the Web Content Accessibility Guidelines define, the lighter colour over the darker
one. Which argument is which does not change the answer.

### `CONTRAST_FLOOR`


Level AA of the Web Content Accessibility Guidelines, for normal text.

### `FontFile`

```
interface FontFile {

  readonly name: string;
  readonly weight: number;
  /** The file, as a path under `fontsRoot`. */
  readonly path: string;
}
```

One file on disk, and the name the application registers it under. The two strings differ, so a
style names the registered name and never the path.

### `FontFamily`

```
interface FontFamily {
  /** What the foundry calls the cut that ships, which can be narrower than the design's name. */
  readonly family: string;
  readonly licence: string;
  /** The licence file, as a path under `fontsRoot`. */
  readonly licencePath: string;
  /** The first line of that file, so a swapped licence is caught rather than trusted. */
  readonly copyright: string;
  /** A name the licence reserves, which a modified build may not keep. Absent when it reserves none. */
  readonly reservedName?: string;
  readonly source: string;
  readonly files: Readonly<Record<FontWeightName, FontFile>>;
}
```

A face, its files, and the terms they travel under. A test reads the licence fields against the
file on disk, so a face cannot ship without its licence beside it.

## `packages/tokens/src/type.ts`

### `FaceName`

```
type FaceName = 'heading' | 'text' | 'numeric';
```

Three faces, each with a job: the serif carries a heading, the humanist sans carries running
text, and the monospaced face carries a number so a digit does not shift as it changes.

### `face`

```
const face: Readonly<Record<FaceName, string>>
```

The family the design names. The cut that ships can be a narrower one, and `fonts` carries that
name, so the two are not the same string.

### `TypeSizeName`

```
type TypeSizeName = 'display' | 'title' | 'heading' | 'body' | 'small' | 'label';
```

Six sizes. A screen that wants a seventh is saying something one of the six already says.

### `TypeStyle`

```
interface TypeStyle {
  readonly size: number;
  readonly lineHeight: number;
  readonly face: FaceName;
  readonly letterSpacing: number;
}
```

A size never travels without its line height and its face, because a line height chosen at the
call site is the one that drifts.

### `typeScale`

```
const typeScale: Readonly<Record<TypeSizeName, TypeStyle>>
```

Points. Every line height is at least `LINE_HEIGHT_FLOOR` times its size, and a test holds it
there.

### `typeSizeNames`

```
const typeSizeNames: readonly TypeSizeName[]
```

The scale as data, from the largest size to the smallest.

### `LINE_HEIGHT_FLOOR`

```
const LINE_HEIGHT_FLOOR = 1.2
```

A multiple of the size. Under this a line sits too close to the one beneath it, and the running
text is where it is felt first.
